# Issue와 PR 규칙

Issue의 제목, 본문, 결과 댓글을 쓰는 규칙이다. PR 제목과 본문에도 같은 규칙을 쓴다. 지금은 PR을 쓰지 않고 실행 브랜치를 로컬에서 main에 합친다([합치기](commits.md#합치기)).

## 제목

무엇을 왜 하는지 드러나게 쓰고, "보완", "변경", "추가", "확대" 같은 행동 명사로 끝내는 개조식으로 쓴다.

- 꼴: "<목적이나 결과>하도록 <대상> <보완, 변경, 추가>" 또는 "<대상>을 <어떻게> 변경하고 <대상> 확대"
- 예: "지도 좌표를 서버 응답과 비교하도록 스크립트 보완", "프로필 사진 레이아웃 변경 및 메뉴 글자 크기 확대"
- "홈 화면 새 디자인"처럼 명사만 늘어놓으면 무엇을 왜 하는지 보이지 않는다. "~한다"로 끝내지 않는다.
- 대상의 이름은 사용자가 부르는 대로 쓴다(예: "프로필 사진", "글자").

## 본문

- 개조식으로, 사람이 바꾸는 것이나 화면에 보이는 것을 쓴다.
- 문장은 [커밋 규칙의 문장 절](commits.md#문장)대로 쓴다. 예: "사진이 왼쪽에 들어온다" 대신 "사진을 왼쪽에 넣는다".
- 판정 기준(Acceptance criteria)은 본문에 체크박스 목록으로 둔다.

## 판정 기준 체크박스

- 체크박스는 Issue 본문에만 둔다. 결과 댓글에는 체크박스를 두지 않는다.
- 검수를 통과하면 오케스트레이터가 본문의 체크박스를 체크한다. 본문을 파일로 받아(`gh issue view <번호> --json body --jq .body`) `[ ]`만 `[x]`로 바꾸고 `gh issue edit <번호> --body-file <파일>`로 올린다. 기준 문장은 바꾸지 않는다.

## 결과 댓글

검수를 통과한 티켓에 다는 댓글이다. 첫 줄에 판정과 커밋을 쓰고, 그 아래에는 체크만으로 드러나지 않는 것(측정값, 기준 밖 변경)만 쓴다. 판정 기준 목록은 댓글에 다시 옮겨 적지 않는다. 더 쓸 것이 없으면 첫 줄로 끝낸다.

```
검수 통과(커밋 1607871).

- 1440px에서 다크 모드 버튼과 네비게이션 줄의 세로 중심 차이 0px
- 기준 밖 변경: 소개, 놀이터 페이지도 같은 폭(720px)으로 맞춤
```

상위 스펙 Issue의 결과 댓글에는 닫은 하위 티켓과 배포한 커밋을 쓴다.

## 리뷰와 검수 시점

- **스펙 Issue, 티켓 Issue, PR 본문:** 등록하기 전에 리뷰어와 검수자가 이 문서를 기준으로 본다. 둘 다 통과한 초안을 사용자에게 보이고, 사용자가 정한 뒤 등록한다.
- **결과 댓글과 본문 체크 상태:** 검수 회차에서 검수자가 판정 기준과 함께 판정한다. 통과하면 사용자에게 묻지 않고 본문을 체크하고 댓글을 단다.
- 모든 글은 [AGENTS.md](../../AGENTS.md)의 "공개 저장소" 절을 따른다.
