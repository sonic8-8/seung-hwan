# 커밋 규칙

## 첫 줄

문어체 한국어 한 문장을 72자 이하로 쓰고, "추가", "수정", "삭제", "변경", "이동" 같은 명사로 끝낸다. 문장에는 바꾸는 목적, 바꾸기 전의 상태, 바꾼 뒤의 상태가 드러난다.

- 앞에 Angular 타입(`feat`, `fix`, `docs`, `style`, `refactor`, `perf`, `test`, `build`, `ci`, `chore`, `revert`)을 붙인다.
- 바꾼 모듈이 분명하면 그 모듈이나 파일의 실제 이름을 괄호 안에 범위로 쓴다.
- 관련 Issue가 있으면 끝에 `#<번호>`를 붙인다.

예:
- `fix(nav-link): 키보드 초점이 잘 보이도록 밑줄을 가리던 초점 테두리 간격을 4px로 수정`
- `docs: 빌드 대기 시간을 줄이기 위해 작업 중 화면 확인을 Docker 빌드에서 개발 서버로 변경 #16`

## 본문

필요할 때만 쓴다. 원인, 구현 방식, 검증 결과 순서로 제목에 없는 내용만 쓴다.

## 문장

ASD-STE100으로 쓴다. 이 저장소에서 더 지키는 것:

- 커밋 하나에 변경 하나를 담는다.
- 용어는 정확한 전체 이름으로 쓴다("개발 서버", "저장소").
- 처음 읽는 사람이 첫 줄만 보고 무엇이 바뀌었는지 알 수 있게 쓴다. 문서 안 번호나 절 이름(예: "흐름 3") 대신 그 단계나 대상의 이름(예: "리뷰 단계")을 쓴다.
- 나열은 뜻에 맞는 말("그리고", "또는")이나 쉼표로 잇는다. 가운뎃점은 어느 뜻인지 알 수 없다.

## 합치기

실행 브랜치는 `git merge --no-ff`로 main에 합치고, merge 커밋 첫 줄은 `chore: <브랜치>를 main에 병합`으로 쓴다. Issue 댓글과 실행 기록에 커밋 번호를 적으므로, 커밋 번호를 그대로 두는 이 방식으로만 합친다.
